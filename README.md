> Analysis of a public benchmark dataset. **Not** a deployed monitoring system — nothing here should be used to decide that real water is safe to drink.

**Question:** *Which water-quality parameters best indicate unsafe water, and can a model flag unsafe samples reliably enough to help prioritize lab testing?*

A false positive wastes a lab test; a false negative lets unsafe water through. So this project does not optimise accuracy — it fixes a recall target on the unsafe class and reports the precision achievable there. Throughout, **UNSAFE is the positive class** (`unsafe = 1 - Potability`).

## Results

Dataset: 3,276 samples, **61.0% unsafe** — note unsafe is the *majority* class, so flagging everything already gives 100% recall. Precision at high recall is the scarce quantity.

**Cross-validated ROC-AUC** (5-fold × 3 repeats, training set only):

| Model | CV ROC-AUC |
|---|---|
| Random Forest **(final)** | 0.688 ± 0.018 |
| Gradient Boosting | 0.668 ± 0.021 |
| XGBoost | 0.665 ± 0.016 |
| LightGBM | 0.659 ± 0.020 |
| Guideline rule baseline | 0.528 ± 0.018 |
| Logistic Regression | 0.510 ± 0.022 |
| Dummy (majority class) | 0.500 ± 0.000 |

**Final model on the held-out test set** (656 samples, used once; 95% CI from 2,000-resample bootstrap):

| Metric (UNSAFE = positive) | Value | 95% CI |
|---|---|---|
| ROC-AUC | 0.693 | [0.651, 0.733] |
| PR-AUC | 0.752 | [0.705, 0.800] |
| Recall (UNSAFE) | 0.887 | [0.854, 0.918] |
| Precision (UNSAFE) | 0.674 | [0.634, 0.712] |
| Balanced accuracy | 0.608 | [0.574, 0.641] |

**Threshold 0.438** was chosen on cross-validated *training* predictions to reach 90% recall at the best precision. Against the default 0.5 it catches 58 more unsafe samples for 44 more wasted lab tests (recall 0.743 → 0.887).

## Key findings

1. **High recall is achievable only by flagging most of the supply.** The model beats "test everything" on precision at matched recall, but the saving is modest and paid for in missed unsafe samples. Whether that trade is acceptable is a policy call, handed over as a number rather than resolved here.
2. **Published drinking-water standards do not explain these labels.** A rule built from verified WHO / BIS / US EPA limits flags **100%** of samples and scores no better than chance: `Solids` breaches the BIS permissible TDS limit in 99.9% of rows (median ≈ 21,000 vs a 2,000 mg/L limit) and `Chloramines` breaches the EPA MRDL in 97.3%. These columns are not on drinking-water scales.
3. **The model and the guidelines agree on *which* parameters matter, not *where the lines sit*.** Top features (`ph`, `Sulfate`, `Hardness`) are all regulated; the two with no verifiable limit (`Organic_carbon`, `Conductivity`) score ~0 importance — `Conductivity` slightly negative, i.e. noise.
4. **Only non-linear models find signal.** Logistic regression sits at chance, so whatever structure exists is interaction-driven and weak.
5. **The errors are not a tuning problem.** Missed and caught unsafe samples differ by <1% in median `ph`, `Sulfate` and `Hardness`. There is no sub-population to repair.

## Limitations

- **Label quality is unknown and is likely the binding constraint.** The source does not state how `Potability` was determined; the data is widely believed to be synthetic. The dataset, not the method, sets the ceiling.
- Two columns contradict their documented units (see finding 2), so the guideline baseline degenerates into "flag everything". Reported rather than silently rescaled.
- Missingness: `Sulfate` 23.8%, `ph` 15.0%, `Trihalomethanes` 4.9% — imputed, not measured.
- No time, location or treatment information; 3,276 rows is small for nine-way interactions; a single 656-row test set.
- `Conductivity` and `Organic_carbon` are excluded from the rule baseline because no numeric drinking-water limit could be verified for either. WHO also publishes no single total-THM value (it is a fractional-sum rule over species), so the US EPA aggregate MCL was used instead.

## Method

Stratified 80/20 split (seed 42) → all preprocessing inside `sklearn` Pipelines so imputer and scaler statistics refit per CV fold → randomised search (40 candidates) over 5-fold CV, with the imputation strategy as a tuned hyperparameter → threshold selected on cross-validated *training* predictions → **test set scored exactly once**, with bootstrap CIs.

Leakage discipline is enforced by tests, not convention: `tests/test_pipeline_no_leakage.py` poisons the test set and asserts the fitted statistics do not move. Every number in this README is generated by `src/aqua_seq/report.py` from `results/metrics/`, so it cannot drift from the code.

## Reproduce

```powershell
# Windows PowerShell
python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python scripts\run_all.py
```

```bash
# Linux / macOS
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python scripts/run_all.py
```

Regenerates every metric and figure from the raw CSV. Python 3.10+ (verified on 3.12.10), seed `42`, ~14 min. Quality gate: `pytest` (34 tests), `black --check src scripts tests`, `ruff check src scripts tests`.
